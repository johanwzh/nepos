# Pull request checklist

Open the PR from your fork against `main` of `johanwzh/nepos`. The title is a plain sentence naming the change. No automatic checks run on pull requests (the only workflow runs when `main` is pushed), so every check below is yours.

## Run these first

In Git Bash or any POSIX shell, from the repo root (`<start-commit>` is the commit you branched from):

```bash
npm ci && npm test                                   # all tests, then tsc: must end green
git diff --name-only <start-commit> HEAD             # only files the work needs
git diff --name-only <start-commit> HEAD | grep -E "(^|/)private/|\.env|secret"   # must print nothing
git log --format='%an <%ae>' <start-commit>..HEAD | sort -u                        # only your own identity
```

## Tick before you open it

- [ ] Tests were written first, and `npm test` is green: Vitest passes and `tsc` prints nothing.
- [ ] Tests for the new output compare the whole text with an expected file that was not generated by the code under test.
- [ ] Only files the work needs have changed: no unrelated edits, no reformatting.
- [ ] No new dependency. `package.json`, `package-lock.json`, `src/version.js` and `.github/workflows/` are untouched.
- [ ] A feature that should not reach production yet sits behind a flag, and every entry point is hidden by it.
- [ ] Writes to the project folder go through `runAction()`; redraws go through `onRefresh`.
- [ ] Every new UI text exists in English and Norwegian, with English UI names and a calm tone. The PR lists the new keys, so the maintainer can check the Norwegian wording.
- [ ] ERN files and project JSON files: untouched, **or** older files still open (a tolerant reader or a format step), with the docs and tests that go with it. `tests/project/upgrade.test.js` is green.
- [ ] The normal Entur NeTEx export is unchanged, and the PR says how you checked ([conventions.md](conventions.md), "The normal NeTEx export").
- [ ] Test data is made up. The diff holds no real names, e-mail addresses, timetables or secrets, and nothing from `private/`.
- [ ] Written for a stranger: nothing in code, comments, test names, docs or commit messages names people, teams or customers, ticket or item numbers, or dates of requests.
- [ ] Commits carry your own identity.
- [ ] A changelog line is added **only if you were asked to** (see "Changelog" in [conventions.md](conventions.md)).
- [ ] No user-guide text.

## What the PR description must say

```markdown
## What this adds
Two or three sentences from the user's point of view, with English UI names.

## Branched from
Commit: <hash>. Branch: <name>.

## How to try it
`npm run dev`, where the entry point is, what to click. If there is a flag: `<NAME>` (on in a dev build, off in production).

## Tests
- New tests: <files>.
- `npm test`: <the "Tests N passed" line>, and tsc printed nothing.

## Files
Added: <list>. Changed: <list>.

## UI texts
New keys, in English and Norwegian: <list>.

## Project files and formats
No ERN or project-file change. Or: what changed, how older files still open, the tests and docs.

## The normal export
Not touched. Or: which files you touched and how you checked the output is unchanged.

## Test data
Made up. Where it is.

## Open questions
Anything left open, and every place where you had to choose.
```

## What gets the closest look

The maintainer reads the whole diff before running anything. These are read first, and none belongs in a PR unless the change is about it:

- `package.json`, `package-lock.json`, and any script such as `postinstall`
- `.github/workflows/` and `vite.config.js`
- a `fetch` or other call to a host that is not already used
- `eval` or `new Function`
- `innerHTML` with text from a project file or the network
- anything that touches `private/` or credentials
